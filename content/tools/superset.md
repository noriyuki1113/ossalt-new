Apache Superset（スーパーセット）は、データベースのデータをグラフやダッシュボードにして、チームで共有するためのBIツールです。Apacheソフトウェア財団のプロジェクトで、公式は「多くのチームで、商用のBIツールの代わりになる、または補える」と説明しています。画面の日本語翻訳もあります。TableauやLookerの代わりとして使われています。

### できること

公式のREADMEにある、主な特徴です。

- **コードを書かないグラフ作成**：画面の操作で、グラフをすばやく作れます。
- **SQLエディタ（SQL Lab）**：SQLを書いてデータを調べ、その結果をそのままグラフにできます。
- **ダッシュボード**：作ったグラフを並べて、絞り込みの操作つきで共有できます。
- **簡易な意味づけの層（セマンティックレイヤー）**：独自の切り口（ディメンション）や指標（メトリクス）を定義できます。
- **多くの種類のグラフ**：棒グラフなどの基本のものから、地図を使ったものまであります。
- **キャッシュ**：データベースへの負荷を軽くするための仕組みを、設定できます。
- **権限と認証**：役割ごとの権限を設定できます。認証の方法も拡張できます。
- **API**：プログラムから操作できます。

### 接続できるデータベース

Pythonのドライバー（DB-API）とSQLAlchemyの方言があれば、SQLを話せるデータベースやデータエンジンにつなげます。公式のREADMEには、Amazon Athena、Redshift、BigQuery、Snowflake、ClickHouse、MariaDB、Microsoft SQL Server、MongoDB、Oracle、Trino、SQLite、Googleスプレッドシートなど、多数が並んでいます。使うデータベースが対応しているかは、公式の[対応データベースの一覧](https://superset.apache.org/docs/databases)で確認してください。

### Metabaseとの違い

[Metabase](/tools/metabase/)は、SQLを書かなくても集計でき、エンジニアでない人にも使いやすい作りです。Supersetは、グラフの種類の多さと、SQLでの自由な分析に強みがあり、データを扱う担当者向けです。詳しくは「[MetabaseとSupersetの違い](/compare/metabase-vs-superset/)」を参照してください。

### 向いている人・向かない人

- **向いている**：データを扱う担当者がいて、SQLでの分析とダッシュボードを、社内で共有したい組織。グラフの表現を細かく選びたい人。
- **向かない**：運用できる人がいない小さなチーム。まずはSQLなしで手早く集計したい場合は、Metabaseのほうが軽く始められます。

### 構成要素と導入方法

公式の説明によると、Supersetは次の部品でできています。

1. **アプリ本体**
2. **メタデータのデータベース**：グラフやダッシュボードの定義、利用者の情報、ログなどを保存します。PostgreSQLとMySQLで動作確認されています。分析の対象のデータとは別のものです。
3. **キャッシュの層**（任意）
4. **ワーカーとビート**（任意）：非同期のクエリ、レポートのメール送信などを実行します。

アラートとレポート、キャッシュ、非同期クエリ、ダッシュボードのサムネイルといった機能は、任意の部品がないと使えません。

導入方法は3つあります。

- **Docker Compose**：公式が「試すのに最適」とする方法です。アプリ、PostgreSQL、Redis、Celeryのワーカーとビートが、まとめて立ち上がります。
- **Kubernetes**：公式が、本番では最良の方法と説明していますが、Kubernetesを扱える人が必要です。
- **PyPI（Pythonのパッケージ）**：コンテナの知識は要りませんが、各部品を自分でつなぐ手間が最も大きいと説明されています。この方法で入れるのはアプリ本体だけなので、キャッシュなどは自分で用意します。

### 試してみる手順

公式のクイックスタートは、Docker、Docker Compose、Gitがある環境で、リポジトリを取得し、版を指定して `docker compose -f docker-compose-image-tag.yml up` を実行する流れです。起動すると `http://localhost:8088` で開け、初期のアカウントは `admin` / `admin` です。**公式は、この方法を本番には勧めていません。**

### つまずきやすい点

- **ドライバーが入っていない**：公式の説明では、既定の `lean` 画像には、メタデータのデータベース用のドライバー、データウェアハウス用のドライバー、レポート用のヘッドレスブラウザが含まれません。自分で画像を拡張する必要があります。
- **`-dev` 画像は本番向きではありません。** 一部のドライバーは入っていますが、rootで動くため、公式は本番では勧めていません。
- **古い `docker-compose` だと、起動時にエラーになることがあります。** クイックスタートに、`docker compose`（スペース区切り）を使うよう案内があります。

### 運用で気をつけること

- **メタデータのデータベースは、必ずバックアップしてください。** 公式は、クイックスタートやPyPIの既定のSQLite、Docker Composeに付属のPostgreSQLのコンテナのボリュームは、どちらも本番には勧めないと説明しています。本番では、別に管理されたデータベースを使い、定期的にバックアップします。
- **設定は `superset_config.py` に書きます。** 最低限、`SECRET_KEY` と `SQLALCHEMY_DATABASE_URI` を変えるよう、公式が案内しています。
- **本番の Web サーバー**：公式は、Gunicornを非同期モードで使うことを勧めています。`superset run` や `flask run` の開発用サーバーは、本番向けではありません。
- **ログインの方法**：OAuth2やLDAPなどの認証にも設定できます。

### 注意点

- **秘密の鍵（SECRET_KEY）を、必ず自分で生成したものに変えてください。** 公式は、この鍵がセッションのクッキーの署名と、メタデータのデータベースに保存する機密情報の暗号化に使われると説明しています。本番で設定していないと、サーバーが起動しません。`openssl rand -base64 42` で生成できます。鍵を変えるときは、`PREVIOUS_SECRET_KEY` に古い鍵を入れて `superset re-encrypt-secrets` を実行する手順があります。
- 初期のアカウント（admin / admin）は、試す環境だけで使い、公開する環境では変更してください。
- つなぐ社内のデータベースには、読み取り専用のアカウントを使うと安全です。
- 導入と運用の手間は、Metabaseより大きめです。
- ライセンスはApache-2.0です。

ほかの候補は、[Tableauの代替](/alternatives/tableau/)のページで比べられます。
