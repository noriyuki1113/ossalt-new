**結論：できることは近く、どちらもAPIの入口として、認証・回数の制限・ログなどをまとめて行えます。利用の例や情報の多さを重視するならKong、Apacheのプロジェクトとして運営され、設定を再起動なしで動的に変えられる作りを重視するならAPISIXです。**

- **Kongを選ぶ場合**：APIゲートウェイの定番で、プラグインが多く、解説の情報も豊富です。開発元の企業が、有料版やクラウド版も提供しています。
- **APISIXを選ぶ場合**：Apache Software Foundationのプロジェクトです。経路やプラグインの設定を、ゲートウェイを再起動せずに変えられる作りに力を入れています。管理用の画面（ダッシュボード）も用意されています。

**選ぶときのコツ**：社内ツールをいくつか公開するだけなら、APIゲートウェイは大がかりです。まずは[Traefik](/tools/traefik/)などのリバースプロキシで足りるかを考えましょう（「[KongとTraefikの違い](/compare/kong-vs-traefik/)」）。

**共通の点**：どちらも、Dockerでの導入方法を確認できています。ライセンスはどちらもApache-2.0です。

詳しくは[Kongとは](/tools/kong/)、[AWS API Gatewayの代替](/alternatives/aws-api-gateway/)のページを参照してください。
