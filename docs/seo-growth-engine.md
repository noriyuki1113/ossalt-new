# SEO Growth Engine（手動実行・読み取り専用）

既存ページの検索流入を増やすための、**手動で回す**改善サイクルです。新規記事の量産ではなく、Search Console（GSC）の実測を根拠に、検索順位5〜20位付近の既存ページを見直します。

- 外部通信・認証情報・課金APIは使いません。入力はGSC画面から手動でエクスポートしたCSVだけです。
- 定期実行（GitHub Actions）はありません。
- **GSCの数値・CSVは公開リポジトリに入れません。** 入力は `agency/data/`、出力は `reports/seo/`（どちらも gitignore 済み）に置きます。

## 道具

| コマンド | 役割 |
| --- | --- |
| `npm run seo:growth -- rank --cur <直近28日> --prev <前28日>` | 2期間を比較し、改善候補（最大10件）・カニバリゼーション候補・データ不足を出す |
| `npm run seo:growth -- effect --before <変更前> --after <変更後>` | 変更履歴（`agency/ledger.json`）の各項目の、変更前後を同条件で比べる |
| `npm run seo:investigate` | ビルド済みサイト（`out/`）の、サイトマップ差分の分類・title長超過の優先評価 |
| `node scripts/seo-ledger.mjs add\|due\|record` | 変更履歴と確認期限（既存） |
| `node scripts/seo-audit.mjs` | テクニカルSEOの監査（既存） |

QI（品質監査）は、`npm run qi:full` の結果（`reports/quality/<id>/audit.json`）を `--qi auto` で読み込み、内容の充実度として採点に使います。

## データの取り方（B：手動エクスポート）

比較の精度は、**2期間の条件をそろえること**で決まります。次の手順で、直近28日と前28日を同じ条件で取ります。

### 1. 期間を決める（絶対日付で指定する）
GSCは直近2〜3日のデータが未確定です。たとえば 2026-11-03 に取るなら次のとおりです。

| | 開始 | 終了 |
| --- | --- | --- |
| 直近28日 | 2026-10-05 | 2026-11-01 |
| 前28日 | 2026-09-07 | 2026-10-04 |

「過去28日間」のような相対指定ではなく、**カスタムの日付**で指定してください。相対指定だと、エクスポートに期間が残らず、前の期間として使えるか検証できません。

### 2. 同じ条件でエクスポートする（2期間とも）
1. GSC → 検索パフォーマンス → 検索結果。
2. 検索タイプ：**ウェブ**。国・デバイスは、**両方の期間で同じ**に（全体なら絞り込まない）。
3. クエリのフィルタ：ブランド検索（`ossalt`）を除外する。**両方の期間で同じ条件**にする。
4. 下の表を、それぞれの期間で開き、右上の「エクスポート」→ **CSVをダウンロード**（ZIPの中に `クエリ.csv`・`ページ.csv`・`デバイス.csv`・`フィルタ.csv` などが入ります）。
5. ZIPを展開し、フォルダごと置く。
   - `agency/data/export-2026-11-03-current/`（直近28日）
   - `agency/data/export-2026-11-03-previous/`（前28日）

### 3. 期間などの申告（`meta.json`）
各フォルダに `meta.json` を置くと、エクスポートに残らない条件を申告できます。

```json
{
  "from": "2026-10-05",
  "to": "2026-11-01",
  "brandFiltered": true,
  "pagesNonbrandConfirmed": true
}
```

`from` と `to` を書かない場合は、実行時に `--cur-from 2026-10-05 --cur-to 2026-11-01 --prev-from … --prev-to …` で指定できます。ブランド除外を `brandFiltered` で申告しないと、「未確認」と表示されます。

### 4. 実行
```bash
npm run seo:growth -- rank \
  --cur agency/data/export-2026-11-03-current --prev agency/data/export-2026-11-03-previous \
  --site out --qi auto --out reports/seo/growth/rank.md
```
`--site out` は、転送ページ・noindexのページを候補から外すために使います（先に `npm run build`）。

### 5. クエリとURLの対応（任意・推奨）
GSCの「クエリ」と「ページ」の表は別々で、**URLとクエリの対応は、そこからは分かりません**。対応が必要な評価（検索意図の一致・カニバリゼーション）には、優先したいページごとに、ページを「完全一致」でフィルタして「クエリ」の表をエクスポートし、1つの `pairs.csv`（列：`クエリ,ページ,クリック数,表示回数,CTR,掲載順位`）にまとめて、期間のフォルダに置きます。まず、候補の上位5〜10ページだけで十分です。

## 比較の条件と、止まる場合

条件がそろわないときは、**比較しません**（理由をレポートに出します）。

- 止める：期間の長さが違う／期間が重なっている／検索タイプ・国・デバイスの絞り込みが違う／ブランド除外の有無が違う／必要な表が両方に無い。
- 「未確認」と表示する：絶対日付が無い／ブランド除外の申告が無い／国・デバイスのフィルタ行が無い（絞り込みなしと仮定した、と明記）。
- 相対表記（過去28日間）の2つのエクスポートで、エクスポート日の差が期間より短いときは、期間が重なっているとして止めます。

## データの限界の扱い

- **行数上限**：GSC画面のエクスポートは、表ごとに最大1,000行です。上限に達した表は『全件ではない』とし、片方の期間にだけある行を「新規」「消えた」と断定しません（`unverifiable`）。
- **匿名化クエリ**：CSVには含まれません。デバイス別の合計との差を『カバー率』として表示し、全件として扱いません。
- **少数の表示回数**：表示回数が少ない行は、順位の増減を判断しません。
- 全体を取りたい場合は、GSC APIかBigQueryへの一括エクスポートが必要です（現時点では導入しません。認証情報の準備が必要です）。

## 優先度スコア

`scripts/seo-priority.mjs` の採点（表示回数・順位帯・同順位帯のCTR中央値・検索パターン・ページ種別・実装コスト）に、次を追加しました。各係数に『実測』か『仮説』を付けます。**仮説は計算の仮定であり、成果の予測ではありません。** 入力が無い項目は、効かせずに『データ不足』として列挙します。

| 追加 | 内容 |
| --- | --- |
| 前期間との比較 | 順位の下落（確認を優先）・表示の増加・すでに改善中（効果を見てから）。少数・片方のみの行は効かせない |
| 検索意図とページ種別 | 検索パターン（比較・代替・ライセンス等）に自然なページ種別と違うと下げる（新規ページの前に意図を確認） |
| 内容の充実度（QI） | QI評価C＝改善余地が大きい、A＝すでに充実 |
| AI Overview | 確認できたクエリだけ。未確認は『未確認』と表示 |

- CTRの改善余地は仮説です。推定クリック増加は、確実な成果として表示しません。
- 『平均順位10.7』のような未検証の数値は、計算に使いません。

## 効果検証

1. 変更を公開したら `seo-ledger.mjs add` で記録する（数値は書かない）。
2. 変更日より前に終わる28日と、変更日から7日以上あとに始まる28日を、同じ条件でエクスポートする。
3. `npm run seo:growth -- effect --before … --after …`。
4. 結果は『兆候』です（改善・悪化・変化小・判断保留・評価不能）。**成功の断定はしません。** 同じURLの他の変更、季節性、変更直後の不安定さ、少数の表示回数を注記します。
5. 記録の候補（`suggestedOutcome`）は自動では書き込みません。確認して `seo-ledger.mjs record` で記録します。

## サンプルデータ

`scripts/fixtures/gsc-sample/` は、テスト用の**架空のデータ**です（`SAMPLE.txt` が目印）。`--allow-sample` を付けないと読み込めず、読み込んだレポートには「サンプル（架空）」と表示されます。実測値として扱わないでください。

## 守ること
- 統合・削除・canonical変更・301・noindexは個別の承認が必要です。このツールは候補を出すだけです。
- title・descriptionの一括変更は、根拠が揃うまで行いません（`docs/seo-site-investigation-20261103.md`）。
