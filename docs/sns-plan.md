# X・Bluesky 運用の構想

ossalt.jp の X・Bluesky アカウントを、サイトへの入口として育てるための方針です。
投稿は運営者が手で行います（自動投稿はしない）。下書きは毎週月曜に自動で作られます（後述）。

## 1. アカウントの立ち位置

**「いま使っているSaaSの代わりになるオープンソースを、データで紹介する日本語アカウント」**

- 紹介するのは「〇〇の代わり」という切り口。ツール名だけでは知らない人に届かないが、「Notionの代わり」なら自分ごとになる
- 数字（スター数・ライセンス・更新状況・日本語対応）を必ず添える。感想ではなく、確かめられる情報で信頼を積む
- 運営の裏側（どう作っているか、何が伸びたか）も見せる。個人で運営しているサイトは、作り手が見えるほど応援されやすい

## 2. 投稿の5つの柱

| 柱 | 内容 | ねらい |
|---|---|---|
| ① 〇〇の代わり | SaaS 1つを取り上げ、代わりになるOSSを3件まで紹介 | 一番クリックされやすい型。代替ページへ誘導 |
| ② 新着・更新 | 新しく掲載したツール、新しいバージョンが出たツール | 「このアカウントを見ていれば新しいものが分かる」 |
| ③ データ・ランキング | スターが伸びたOSS、日本語対応の割合など | 引用・リポストされやすい。はてな・Zennの記事とも連動 |
| ④ 日本語で使えるOSS | 画面が日本語に翻訳されているツールを1件ずつ | 日本語サイトならではの価値。英語圏のアカウントと差がつく |
| ⑤ ブログ・運営の裏側 | 新しい記事のお知らせ、サイトの改善、数字の振り返り | 作り手が見えることで、フォローと応援につながる |

## 3. 1週間の型（1日1投稿）

| 曜日 | 柱 | 例 |
|---|---|---|
| 月 | ① 〇〇の代わり | 「Postmanの代わりになるオープンソース、3件を比べています」 |
| 火 | ⑤ ブログ（新しい記事の公開日） | 「ブログを書きました：〇〇」 |
| 水 | ④ 日本語で使えるOSS | 「日本語の画面で使えるオープンソース：〇〇」 |
| 木 | ② 新着・更新 または ③ データ | 「この1週間でスターが多く増えたOSS」 |
| 金 | ⑤ 運営の裏側 または 問いかけ | 「〇〇の代わり、何を使っていますか？」 |

- 毎日続けるのがつらければ、**月・水・金の週3回**でもかまわない。止めないことが一番大事
- 時間帯は、平日の昼（12時台）か夜（20〜22時）が目安。実際の反応を見て合わせる
- X は予約投稿（投稿画面の時計のアイコン）を使うと、週末にまとめて準備できる

## 4. 毎週の流れ

1. **月曜の朝**：GitHub の `docs/sns/drafts/<日付>.md` に、その週の下書きが自動で作られる（ワークフロー「SNS投稿の下書き」）
2. 下書きから使うものを選び、言い回しを自分の言葉に直す（そのままでも投稿できる文になっている）
3. 数字が大きく動いている投稿（スターの伸びなど）は、念のためツールのページで値を確かめてから出す
4. X は予約投稿で1週間分を入れておく。Bluesky は予約投稿の機能がないので、その日に投稿する

下書きは手元でも作れる：`node scripts/sns-drafts.mjs --stdout`

## 5. 反応を増やすコツ

- **紹介するツールの公式アカウントに言及する。** 開発者は自分のツールが紹介されるとリポストしてくれることが多い（英語圏のOSSでも、日本語の紹介を喜ぶ開発者は多い）。言及するのは、紹介文が正確なときだけ
- **画像を付ける。** ツールのページや比較表のスクリーンショットは、文字だけの投稿より目に留まりやすい
- **X では、リンクを返信欄に置く方法も試す。** 本文にリンクがある投稿は表示が伸びにくいと言われている。本文は情報だけにして、「詳しくはこちら」を自分の返信に付ける。Bluesky は本文にリンクを入れてカードを表示させてよい
- **問いかけで終える。** 「〇〇の代わり、他に知っていたら教えてください」は返信が付きやすく、掲載候補の発見にもつながる
- **ハッシュタグは1〜2個まで。** `#セルフホスト` `#OSS` など。付けすぎると読みにくい

## 6. X と Bluesky の使い分け

| | X | Bluesky |
|---|---|---|
| 主な読者 | 情シス・Web担当・個人開発者など幅広い | エンジニア・技術好きの比率が高い |
| リンク | 返信欄に置く方法も試す | 本文に入れてカードを出す |
| 文字数 | 日本語140文字相当（下書きに文字数を表示） | 300文字 |
| 向いている柱 | ①〇〇の代わり、③データ | ②新着・更新、④日本語OSS、⑤運営の裏側 |

同じ文面を両方に出してかまわないが、反応の良い柱が違うことがあるので、数か月ごとに見直す。

## 7. やらないこと

- **自動投稿・同じ文面の連投はしない。** スパムとみなされ、アカウントが制限される
- **SNSにアフィリエイトリンクを直接貼らない。** VPSの記事などを紹介するときは記事のURLを貼り、紹介料を含む記事であることを `#PR` などで明示する（ステルスマーケティング規制）
- **他のツールやサイトを悪く言わない。** 比べるときは、データの違いだけを書く
- **確かめていないことを書かない。** 「日本語対応なし」ではなく「日本語対応は未確認」。サイトと同じ基準にする
- **運営者の本名やメールアドレスを書かない。** 表示名は Momonga

## 8. 振り返り（月1回）

- アクセス解析（Umami）の「参照元」で、x.com（t.co）と bsky.app からの訪問数を見る
- どの柱の投稿がクリックされたかを、Xのアナリティクスと合わせて確認する
- 反応が良かった柱を増やし、反応が無い柱は形を変える
