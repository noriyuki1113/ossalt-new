## 1. 最終目標と優先の順序

「OSS導入を考える読者が集まり、その価値によってソフトウェア関連企業から継続的な収益を得るプラットフォーム」。

ただし、**短期の収益のために中立性・検索の品質・読者の体験を損なわない**。順序は、読者の価値 → 信頼 → 検索流入 → 計測 → 収益化。

## 2. 3つの事業と、今の判断

| 事業 | 今の段階 | 判断 |
|---|---|---|
| **B. Affiliate**（国内VPS、A8.net） | 唯一の収益源。提携済み4社 | **最優先**。表示（PR・ステマ規制）と計測を直した。次は記事と文脈（Phase 2） |
| **A. Sponsors** | 契約0件。料金の根拠なし | 受け皿（媒体資料・部品・計測）だけ用意。**販売は保留**（4週間以上の計測がそろってから） |
| **C. Intelligence** | 将来の候補 | **開発しない**。需要検証の設計のみ |

## 3. 最終的に採用した戦略

1. **今ある収益源を守り、測れるようにする**（Phase 1）
   - VPS枠に「PR」と、紹介料が入ること・並び順の根拠を言い切りで表示。編集方針・プライバシーポリシーを実態に合わせた。
   - 画面内閲覧（affiliate_viewable）とクリックで、枠・文言ごとのクリック率を出せるようにした。
2. **スポンサーの受け皿を作るが、売り込まない**（Phase 1）
   - `/advertise/` を媒体資料の初版に。実績は「計測中」、読者の属性は「取得していない」、料金は個別見積もり。
   - スポンサー枠は契約0件で何も表示しない。契約を確認した日がないと表示できない（架空の広告を出さない）。
3. **流入と送客を、記事の質で増やす**（Phase 2）
   - 優先テーマ：n8n・Immich・Uptime Kuma・AppFlowy・Directus・Ollama（すべて解説あり。導入・移行・運用の記事が少ない）。既存の解説・ブログの改善を新規の記事より優先する。
   - 各記事で「読者が解決したい問題／OSSALTの独自の情報／適切な収益の導線」を書いてから作る。実機で確かめていない手順を「検証済み」と書かない。AIの下書きは可、公開は人の承認。
   - Ollama のようにGPUが要るものには、提携のないGPUサービスを紹介しない（VPS枠も出していない）。
4. **数字がそろってから、売る・作る**（Phase 2以降）
   - スポンサーの最初の1社は「1か月・実績の報告つきの試験掲載」として個別に決め、それを価格の根拠にする。
   - ダッシュボードは、手入力の記録（R12）が続いてから、サイトの外（非公開リポジトリ＋Cloudflare Access）で検討。

## 4. 絶対のルール（実装での担保）

| ルール | 担保 |
|---|---|
| スポンサー料で順位を変えない | スポンサーの設定はどの並べ替えにも使わない（`src/lib/sponsors.ts`）。枠は本文・比較の後で、一覧・比較表の中に置かない |
| 広告と通常の内容を区別 | 「PR」「スポンサー」の表示（`AdLabel`）、aria-label、注記 |
| 有料のリンクの rel | アフィリエイト・スポンサーとも `sponsored noopener noreferrer` |
| 実績のない数値を販売資料に使わない | `/advertise/` の数値は掲載数（ビルド時のデータ）だけ。アクセス数は「計測中」 |
| 架空の広告を出さない | active の掲載は契約を確認した日が必須（テストで検査） |
| 個人情報を広告主に渡さない | 計測は Cookieなし・個人を特定しない集計のみ。プライバシーポリシーに明記 |
| 実測と予測を混同しない | 会議の記録は「点数は専門的判断」を必須に。収益の指標は数値を持てない |
| 課金・契約を勝手に始めない | 決済・自動の営業メール・新しい提携は作らない |
| 本番データの破壊的変更をしない | DBなし。アフィリエイトのリンクの値は1文字も変えていない |

## 5. KPI と計測の計画

North Star の **月間営業利益** は、現時点では**計算できない**（収益の取得手段がなく、費用・工数も記録していない）。計算の範囲は「A8の承認済み報酬＋スポンサーの入金 − サイトの固定費（ドメインなど）」とし、工数は当面含めない（記録がないため）。

| KPI | 取得できるか | 計画 |
|---|---|---|
| 承認済みのアフィリエイト報酬 | 運営者のみ（A8の管理画面） | 月に1回、非公開の表に記録（R12）。リポジトリには置かない |
| ASPのクリック数 | Umami（運営者） | `affiliate_click` を placement・variant 別に |
| 枠のクリック率 | Umami（運営者） | `affiliate_click` ÷ `affiliate_viewable` |
| スポンサーの問い合わせ | Umami（押した数）＋メール（実際の件数） | `advertise_inquiry` と、届いたメールの件数を両方見る |
| スポンサーの契約件数・収益 | 運営者 | 契約が成立したら記録 |
| 収益関連ページの検索流入 | Search Console（運営者） | ツール詳細・ブログ・Cost Lab |
| コンテンツの制作工数 | 記録なし | Phase 2 で、記事ごとの時間を記録するかを決める |
| 中期（継続率・収益/訪問・収益/記事・回収率） | 収益の実数が必要 | 月次レビューで、取得できたものから |
