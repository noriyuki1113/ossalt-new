SaaSの代わりに、自分たちのサーバーで動かせる「オープンソース」を探していると、「オープンソースなのに、使い方に条件がある」ツールに出会うことがあります。n8n、Dify、Sentry などです。

そこで、SaaSの代わりになるオープンソース 377件のライセンスを分類して、どんな傾向があるかを集計してみました。

**結論から言うと、人気のあるプロジェクトほど、一般的なOSSライセンスではないものの割合が高い傾向がありました。**

## 集計の方法

対象は、[ossalt.jp](https://ossalt.jp/) に掲載している、GitHubで公開されていてアーカイブされていない 377件です。各ツールのライセンス表記（GitHubの公開情報）を、次の基準で分類しました。

| 分類 | 内容 |
|---|---|
| 許容型 | MIT、Apache-2.0、BSDなど |
| コピーレフト | GPLなど |
| ネットワーク型コピーレフト | AGPLなど |
| 弱いコピーレフト | LGPL、MPLなど |
| **ソース公開型** | **ソースコードは公開されているが、一般的なOSSライセンスではないもの**（BUSL、FSL、Elastic License、SSPL、独自のライセンスなど） |
| そのほか | 複数のライセンスから選ぶもの、構成要素ごとに異なるもの、取得できていないもの |

**注意点を先に書きます。**

- この分類は、私が決めた基準によるもので、法的な判断ではありません。何を「一般的なOSSライセンス」とするかは、OSI（Open Source Initiative）の承認の有無など、立場によって意見が分かれます。
- ライセンスの表記は、GitHubの公開情報をもとにしています。複数のライセンスを併用しているプロジェクトでは、実際の条件と異なる分類になっている可能性があります。
- 導入の前には、必ずプロジェクトのライセンス文そのものを読んでください。

## 全体の内訳

| 分類 | 件数 | 割合 |
|---|---|---|
| 許容型 | 192件 | 50.9% |
| ネットワーク型コピーレフト | 77件 | 20.4% |
| コピーレフト | 59件 | 15.6% |
| ソース公開型 | **23件** | **6.1%** |
| 弱いコピーレフト | 15件 | 4.0% |
| そのほか | 11件 | 2.9% |

ライセンスの名前で見ると、多い順に MIT（98件）、Apache-2.0（76件）、AGPL-3.0（74件）でした。AGPL-3.0が、GPL-3.0（38件）の倍近くあるのは、少し意外でした。SaaSの代わりになるツールは、ネットワーク越しに使う性質があるため、AGPLを選ぶプロジェクトが多いのかもしれません（これは私の推測です）。

## 人気のあるプロジェクトほど、ソース公開型が多い

GitHubのスター数で分けて、ソース公開型の割合を見ると、次のようになりました。

| スター数 | 件数 | ソース公開型 | 割合 |
|---|---|---|---|
| 5,000未満 | 64件 | 2件 | 3.1% |
| 5,000〜2万 | 145件 | 10件 | 6.9% |
| 2万〜5万 | 111件 | 5件 | 4.5% |
| **5万以上** | **57件** | **6件** | **10.5%** |

スター5万以上の6件は、n8n、Dify、Open WebUI、LobeChat、NocoDB、tldraw でした。

きれいな右上がりではなく、件数も少ないので、「人気が出るほど増える」と言い切ることはできません。ただ、**スター5万以上の層では、全体の割合（6.1%）の約1.7倍**になっています。

なぜそうなるのか、データからは分かりません。一般に言われる理由としては、人気が出て、企業が資金を得てクラウド版で収益化しようとすると、「他の会社に、自分たちのソフトをクラウドサービスとして再販されること」を防ぐ目的で、独自の条件を加えるケースがある、ということがあります。

## カテゴリによって、大きく偏る

カテゴリ別（7件以上あるもの）では、ソース公開型の割合に、大きな差がありました。

**多いカテゴリ**

| カテゴリ | 件数 | ソース公開型 | 割合 |
|---|---|---|---|
| データベース・表作成 | 9件 | 3件 | 33% |
| アクセス解析・プロダクト分析 | 11件 | 3件 | 27% |
| 監視・エラー追跡 | 17件 | 3件 | 18% |
| ローコード・BI | 7件 | 1件 | 14% |
| 会計・請求書・経費 | 15件 | 2件 | 13% |

**ゼロのカテゴリ**

開発・デプロイ基盤（45件）、認証・パスワード管理（27件）、チャット（13件）、ファイル管理・写真（17件）、ビデオ会議・配信（18件）、メール（10件）などは、**ソース公開型が1件もありませんでした。**

データを抱え込むことで価値が出る分野（データベース、アクセス解析、監視）に、独自の条件が多い、という傾向に見えます。一方で、通信や認証の部品は、一般的なライセンスが多いようです。

## ソース公開型 23件の中身

最後に、23件を、ライセンスの種類別に並べます。

| ライセンス | 件数 | ツール |
|---|---|---|
| BUSL 1.1 | 4件 | Outline、SurrealDB、Budibase、Akaunting |
| Elastic License 2.0 | 3件 | Invoice Ninja、Phoenix、RudderStack |
| FSL 1.1 | 2件 | Sentry、Typebot |
| Sustainable Use License | 2件 | n8n、NocoDB |
| SSPL 1.0 | 1件 | Graylog |
| AGPL-3.0 + Commons Clause | 1件 | Chaskiq |
| 各プロジェクト独自の条件 | 10件 | Dify、Open WebUI、LobeChat、tldraw、NocoBase、Cachet、PLANKA、Anytype、Countly、GoatCounter |

BUSLとFSLは、一定の期間が過ぎると、一般的なOSSライセンスに切り替わる仕組みがあります（切り替わる時期や、切り替え先のライセンスは、ライセンス文で決まっています）。

## 導入するときの確認点

ソース公開型のツールを「使ってはいけない」わけではありません。多くの場合、**自社の業務のために社内で使うことは、認められています。** 確認が必要なのは、次のような使い方です。

1. **他社や顧客に、サービスとして提供する**（再販、マルチテナントでの提供など）
2. **改変したものを、配布する**
3. **一部の機能が有料版だけにある**（無料の版で、必要な機能が使えるか）

自社の中で使うだけでも、「何を禁止しているか」を、一度ライセンス文で確認しておくと安心です。
