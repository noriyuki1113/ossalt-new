### EEA・英国・スイス向けの同意管理（調査結果と未設定事項）
**注意：このセッションは外部サイトに接続できず、以下は私の既知の情報で、公式での再確認が必要。**
- EEA・英国（および後からスイス）の利用者に AdSense で広告を出すには、**Google 認定の同意管理プラットフォーム（CMP）**（IAB の TCF v2.2 に対応）を使う必要がある、というのが Google の公開要件（EU user consent policy）。
- Google が提供する無料の同意メッセージ（AdSense の「プライバシーとメッセージ」から設定）を使う方法がある（公式で最新の手順を確認）。
- **未設定**：CMP、ads.txt（Publisher ID が必要）、広告タグ。いずれも Publisher ID が無い現在は設置していない。架空の値も入れていない。
- 既存の PostHog の同意バナーは、広告の同意とは別。広告のCMPを入れるときは、2つのバナーが重ならない設計を決める必要がある（未設計）。

## 3. P1：OSS詳細ページの監査（399ページ）

- 方法：`node scripts/tool-pages-audit.mjs`（ビルド済みHTMLとデータの照合）。確認項目：title・description・canonical・noindex・h1・構造化データ（BreadcrumbList・SoftwareApplication の整合）・ライセンス表記のデータとの一致・公式リンク・データの取得日・description重複・サイトマップとの整合・内部リンク数・手書き解説の有無と長さ・FAQの定型文の割合。
- 結果（ページの最悪の重要度）：**重大10／中程度77／軽微312／問題なし0**。ページ別は `docs/audits/tool-pages-20261028.md`。

| 問題 | 重要度 | ページ数 | 扱い |
| --- | --- | ---: | --- |
| indexable-not-in-sitemap | 重大 | 10 | **保留（人手判断）**。アーカイブ済み10件が index のまま、サイトマップと一覧から外れている。noindex にするかは、Search Console の流入を見てから（流入のあるページを機械的に除外しない）。robots.txt では遮断しない |
| no-guide | 中程度 | 244 | 手書きの解説が無い（自動の要約とデータが中心）。大量に自動生成しない。優先順位は下記 |
| archived | 中程度 | 10 | 上と同じ10件 |
| thin-guide | 中程度 | 1 | 手書きが600字未満 |
| unverified | 軽微 | 155 | 解説が「未検証」表示（公式資料との照合の記録なし） |
| no-glance | 軽微 | 147 | 「30秒で」要約が無い（8件に追加済み） |

- **問題が出なかった項目**：title・canonical・h1・構造化データの構文、ライセンス表記とデータの不一致、公式リンクの欠落、description の重複、データの取得日の欠落。
- **FAQの定型率**：FAQの回答の約56%（中央値）が、多くのページで同じ文（ツール名を置き換えると一致）。手書きの解説の有無で差が出ない。FAQを減らす・個別化するのは、事実の根拠が要るため未実施（要検討）。
- **手書きの解説を優先する候補**（解説なし・GitHub Stars 上位）：openclaw・hermes-agent・quivr・handbrake・argo-cd・navidrome・prefect・krayin・cap・listmonk。ただし、公式資料の確認が必要。

### 要確認の異常（データ）
- **PocketBase が 2026-10-28 の日次更新で「アーカイブ済み」に変わった**（前日まで false）。最終コミットは2日前。アーカイブ済みのリポジトリには通常コミットできないため、データ取得の誤りの可能性がある。**GitHub で pocketbase/pocketbase の状態を確認してください。** 誤りなら次回の日次更新で戻る見込み。真なら、このツールのページ・比較ページへのリンク整理が要る。
- この影響で、`/tools/appwrite/` と `/tools/pocketbase/` の解説から、存在しない比較ページ2件（appwrite-vs-pocketbase・pocketbase-vs-supabase）へのリンクが切れている（監査で検出）。PocketBase の状態が確定してから直す（誤判定なら自然に解消）。

## 4. P2：独自の解説記事

**今回は、公開できる記事を作っていません（下書きも作っていません）。** 理由：
- 事実の根拠（公式資料）を、このセッションから確認できない。確認していない内容を書くと、「検証済み」と誤解させる恐れがある。
- 候補テーマの多くが、既存の資産と重なる。

| 候補 | 既存との重複 | 判断 |
| --- | --- | --- |
| A Notionから移行するときの注意点 | `/alternatives/notion/` に「移行するときの注意」「Notionのままのほうがよい場合」がある | 重複が大きい。別の切り口（例：Notionの書き出し形式ごとの崩れ方）を、公式資料と実機で確認できる場合のみ |
| B SaaSとセルフホストの3年間の総費用 | Cost Lab がある。料金の事実が要る | 料金表の一次情報（確認日つき）が必要。運営者の入力待ち |
| C 中小企業がOSSを導入する際の失敗要因 | 根拠にできる調査データが手元にない | 保留（体験談の捏造になる） |
| D ライセンス別の商用利用の注意点 | `oss-license-guide` がある | 重複。更新（2026-09-26 時点のデータ）で足りる |
| E Dockerで動くOSSの運用・更新・復旧 | `docker-checklist`・`selfhost-backup-basics` がある | 重複 |

- 公開済みの記事は、`content/blog/` に14件（サイト上の記事一覧は7件表示。差の理由は未調査）。
- 過去の集計値を使う記事は、時点を明記する（`how-to-read-github` を修正：「379件」は2026年9月26日時点の集計）。
- **運営者にお願いしたいこと**：記事にする場合は、公式資料のURLと確認日、実際に動かした場合は環境と手順を教えてください（`docs/verification-guide.md`）。著者・編集責任の表示は `/editorial/` と `/about/` の既存の記載を使う。

## 6. AdSense申請前に必要な手動作業

1. AdSense のアカウント作成と、サイトの追加（Publisher ID の取得）。
2. 運営者情報の公開（運営者名・連絡先）。`NEXT_PUBLIC_OPERATOR_NAME` などの環境変数が未設定（`docs/analytics-foundation.md`）。
3. EEA・英国・スイス向けの CMP の設計（Google の公式手順を確認。PostHog の同意バナーとの共存）。
4. `ads.txt` の設置（Publisher ID 取得後）。
5. PocketBase のアーカイブ判定の確認（§3）。アーカイブ済み10件を index のままにするか、noindex にするか（Search Console の流入を見て判断）。
6. 手書きの解説・記事の事実確認（公式資料の照合）。ここが審査での「独自性・有用性」に最も関わる。
7. 公式の AdSense プログラムポリシーと、サイトの現状（広告が少ない・コンテンツの量・ナビゲーション）を、申請直前に自分の目で確認。
8. 広告設置後のレイアウト（広告枠の予約領域でレイアウトのずれを避ける）の確認。
