# SERP・競合調査の手順書

優先クエリ（`seo:growth rank` の上位候補）の、Googleの上位10件を調べる手順です。**手動実行が前提で、課金APIは使いません。**

## 守ること
- Googleの検索結果を、利用規約に反する方法（自動の大量取得）で集めない。1クエリずつ、人が検索画面で見る。
- 有料API（DataForSEO、UpperSearch など）は、実行前に料金を見積もり、承認を得るまで使わない。
- ドメインオーソリティなど第三者の指標だけで、難易度を決めない。
- 確認できなかった項目は『未確認』と記録する（推測しない）。AI Overview・スニペットなどのSERP機能も同様。

## 準備
- 調査対象は、候補の上位5件程度まで（実データが足りなければ減らす）。
- ログインしていないブラウザ（シークレット）で、日本・日本語。端末（PC／モバイル）を記録する。
- 記録先は `reports/seo/serp/<クエリ>.md`（gitignore 済み）。検索日・端末・場所を必ず書く。

## 記録する項目（1クエリあたり）

| 項目 | 記録の仕方 |
| --- | --- |
| 検索意図 | 上位ページの種類（比較／一覧／公式／解説／フォーラム）の内訳。OSSALTの該当ページの種類と合っているか |
| SERP機能 | AI Overview・強調スニペット・People also ask・動画・画像の有無。見えなければ『未確認』 |
| 上位10件の分類 | 公式・大手メディア・個人サイト・フォーラム（Qiita・Zenn・Reddit等）・比較サイト。偏りを見る |
| 更新状況 | 各ページの更新日（表示があれば）。古い情報が上位にあるか |
| 不足している内容 | 上位が答えていて、OSSALTに無い情報（選定基準、導入条件、注意点、実用例、料金・ライセンスの条件）。**一次資料で確認できる事実だけ** |
| 独自にできること | OSSALTの強み（日本語、ライセンス、保守状況、比較表、Cost Lab・診断への導線） |
| 難易度の所見 | 上位に個人サイト・フォーラムが多い→参入余地あり、など。**根拠の観察を書き、数値化しない** |

## 判断
- 検索意図とページ種別が違う → 新規ページの前に、既存ページの意図・導線を見直す（`seo-priority` の『検索意図とページ種別』の係数と対応）。
- 同じクエリで自社の複数ページが出ている → カニバリ候補（`seo:growth rank` の結果と照合）。統合・canonical・301は個別承認。
- 不足している内容は、一次資料で確認できたものだけ反映する。創作しない。

## 将来、有料のSERP取得を使う場合
実行前に、(1) 対象クエリ数、(2) 1件あたりの料金、(3) 合計の見積もり、(4) 取得するデータの項目を示し、承認を得る。承認前には実行しない。
