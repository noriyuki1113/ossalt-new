# レビューの観点（OSSALT）

PR（自分が書いたもの、他のエージェントや人が書いたもの）をマージ前に見る観点。考え方は agent-skills の code-review-and-quality を、OSSALT向けに短くしたもの。
SEOの内容のレビューは、`.claude/skills/ossalt-seo/SKILL.md` の Review Mode が優先。ここはそれ以外の変更も含めた共通の観点。

## 進め方
1. 目的を読む（PR本文、関連する文書）。何を変え、何を変えないのか。
2. **テストを先に読む。** 何を保証しているか、弱めていないか。
3. 実装・文章・データを読む。
4. 指摘に重大度を付ける。
5. **検証したと書かれていることを、検証する。** 実行した出力が本文にあるか。実行していないものは「未実行」と書かれているか。

## 5つの観点
| 観点 | 問い |
|---|---|
| 正しさ | 目的どおりか。境界・空・例外は。事実は一次情報で裏づけがあるか |
| 読みやすさ | 名前・構造・文章は、初見でも読めるか |
| 設計 | 既存の構成・命名に合うか。同じものを二重に作っていないか |
| 安全 | 秘密・個人情報・Search Console の数値を入れていないか。外部の入力を信用していないか |
| 性能 | 不必要に重くなっていないか（ビルド時間・ページの大きさ） |

## OSSALT固有の確認
- **SEO**: title・canonical・robots・sitemap・公開ページ・URLを変えていないか。変えるなら、承認と影響範囲の説明があるか。`CONSTRAINTS.md` の保護パスに触れていないか。
- **事実**: ライセンス・バージョン・対応状況は、公式の一次情報で確認したものか。確認できないことは「未確認」か。実機で動かしていないものを「実機検証済み」と書いていないか。
- **公開リポジトリ**: Search Console の数値、秘密情報、個人情報が入っていないか。
- **件数・表示**: 件数やtitleの数字が変わるなら、データ由来の変化として説明があるか。
- **ゲート**: テストのスキップ・削除、検査の条件の緩和、抑制コメントの追加がないか。

## 重大度
| ラベル | 意味 | マージ前に直す |
|---|---|---|
| Critical | 壊れる・事実が誤り・秘密の混入・SEOゲートの弱体化 | 必ず |
| Required | 目的を満たさない・テスト不足・規則違反 | 必ず |
| Nit | 好みの範囲（命名・体裁） | 任意 |
| Optional | 良くなるが、必須ではない | 任意 |
| FYI | 共有だけ | 不要 |

## 変更の大きさ
- 目的ごとに分ける。1つのPRに、無関係な変更を混ぜない。
- 文章・コードの差分は、小さいほどよい（目安は数百行以内）。
- **例外**: 自動生成のデータ（`public/data/tools.json` など）、台帳、一括の削除は、行数でなく意図と生成手順で確認する。

## 正直さ
- 見ていない部分を「問題なし」と書かない。「見ていない」と書く。
- 通っていないテストを、通ったと書かない。CIが赤なら赤と書き、原因が自分の変更かを切り分ける。
