# 優先順位の設計

表示回数のランキングではありません。次の要素を組み合わせ、**どれが実測で、どれが仮説か**を、出力の各行（`factors`）に残します。実装：`scripts/seo-priority.mjs`。

| 要素 | 区分 | 使い方 |
| --- | --- | --- |
| 表示回数 | 実測 | 対数で効かせる（大きすぎる値で他を押しのけない）。100回未満は候補にしない |
| 順位 | 実測 | 5〜20位＝内容・内部リンクの強化、5位未満でCTRが低い＝title/descriptionの見直し、21〜40位で表示500回以上＝検索意図の調査 |
| CTRの低さ | 実測 | 外部のCTR表は使わない。**入力データ内の、同じ順位帯の中央値**との比較だけ（行が5件未満の帯は比べない） |
| 改善余地 | 仮説 | 順位が上位に近いほど大きい（計算上の仮定） |
| 検索パターン | 仮説 | 比較（vs）・代替・オープンソース・セルフホスト・ライセンス・導入方法の分類。**分類であって、需要がある証拠ではない** |
| ページ種別（事業上の重要度） | 仮説 | 代替・比較ページを高く見る。コンバージョンを計測していないため、仮説と明記 |
| 実装コスト | 仮説 | title/descriptionは小、内容の強化は中、検索意図の調査（新規ページの要否）は大 |
| 既存ページへの悪影響 | 実測 | 転送ページ・noindexのページは、改善の対象外（`--site out`）。canonical・noindex・URLの変更は承認事項 |
| 検索意図との一致、OSSALT の独自価値、競合との差 | 人の判断（Claude） | STRATEGY に、SERPを読んだ日付つきで書く。点数にはしない |

クエリ集計とページ集計は結び付けません。URLとクエリの対応を評価できるのは、クエリ×ページ（GSCで両方を完全一致で絞ったデータ）だけです。
